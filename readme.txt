Лабораторная работа 1. Парсер пакетов задач

Программа читает пакет олимпиадной задачи и выводит информацию о ней:
название, лимиты, чекер, решения, группы и список тестов.

Что сделано:
  KRSU    - да
  CATS    - да
  EJUDGE  - да
  PCMS2   - нет

Нужен Python 3.10+, сторонние библиотеки не используются.


Как запускать

  python3 main.py ФОРМАТ ПУТЬ_К_ПАКЕТУ

Формат можно писать в любом регистре. Пакет - zip-архив, но можно
указать и уже распакованную папку.

Примеры пакетов лежат в packages/:
  python3 main.py KRSU packages/krsu_A.zip
  python3 main.py KRSU packages/krsu_groups.zip
  python3 main.py CATS packages/cats_area51.zip
  python3 main.py EJUDGE packages/ejudge_sample.zip

krsu_A - настоящий пакет (27 тестов с баллами), krsu_groups - пример
из описания формата с группами, cats_area51 - задача Area 51 (42 теста),
ejudge_sample - пример с пятью группами и 46 тестами.

Если что-то совсем не так (формат не тот, файла нет, архив или XML битый),
программа пишет ошибку в stderr и выходит с кодом 1. Мелкие проблемы,
например тест ссылается на файл, которого нет в архиве, печатаются
в конце в разделе "ПРЕДУПРЕЖДЕНИЯ".


Тесты

  python3 -m unittest -v

Всего 42 теста. Проверяются реальные пакеты из папки 5298, разные
крайние случаи для каждого формата и ошибки при запуске.


Как устроен код

main.py   - запуск, тут создаются все нужные объекты
app/      - ConsoleApp: разбирает аргументы, вызывает чтение и вывод
domain/   - модель задачи (TaskDescriptor, Case, Subtask, HelperProgram)
            и классы ошибок
storage/  - откуда берутся файлы: ZipFileSource для архива,
            FolderFileSource для папки, SourceView для поиска по ним
readers/  - чтение форматов, по папке на каждый:
              krsu/   - testinfo.xml
              cats/   - xml-файл в корне, разбит на секции (заголовок,
                        условие, программы, тесты)
              ejudge/ - problem.cfg и valuer.cfg (у valuer свой
                        маленький лексер и парсер)
              toolkit/ - то, что нужно нескольким форматам: числа, xml,
                         размер памяти, проверка что файлы на месте
report/   - вывод в консоль, отчет собирается из блоков
tests/    - тесты

Все форматы приводятся к одной модели TaskDescriptor. Время хранится
в миллисекундах, память в байтах. То, что есть только в каком-то одном
формате, складывается в словарь specifics и тоже выводится.


SOLID

S - у каждого класса одна задача. Например, FileSource только отдает
    файлы, а искать по ним умеет SourceView. Valuer.cfg разбирают
    два класса: один режет текст на лексемы, второй разбирает грамматику.
O - чтобы добавить новый формат, достаточно написать наследника
    TaskReader и добавить его в standard_catalog(). Так же добавляются
    новые секции CATS, новые блоки отчета и новые опции valuer.cfg.
    Старый код трогать не надо.
L - любой читатель можно подставить вместо TaskReader, архив и папка
    взаимозаменяемы, вывод можно заменить любым TaskRenderer.
I - интерфейсы маленькие: read() у читателя, entries() и load()
    у хранилища, render() у вывода.
D - ConsoleApp получает все зависимости через конструктор и знает
    только про абстракции. Конкретные классы выбираются в main.py.


Особенности форматов

KRSU
  - testinfo.xml может лежать как в корне архива, так и во вложенной папке
  - runtype (0/1/2) выводится словами
  - проверяю, что группы из groupid и prereq существуют и что файлы
    тестов есть в архиве

CATS
  - xml бывает в Windows-1251, кодировка берется из заголовка
  - tlimit в секундах (может быть дробным), mlimit с суффиксами B/K/M/G,
    без суффикса - мегабайты
  - тесты собираются из <Test rank="..."> и <TestRange>. Номера можно
    писать как "1,3,5-10,1-9-2,имя_набора", rank="*" задает значения
    по умолчанию, в путях подставляются %n и %0n
  - <Testset> выводятся как группы
  - чекер может быть задан через stdChecker, <Checker> или
    <Import type="checker">

EJUDGE
  - из problem.cfg берется только секция [problem], кавычки убираются,
    параметр без "=" считается равным 1 (например use_stdin)
  - время в time_limit (секунды) или time_limit_millis, память
    max_vm_size с суффиксами K/M/G
  - valuer.cfg разбирается по грамматике из документации: блок global,
    группы с tests, score, test_score, requires. Остальные опции группы
    (offline, skip, 0_if и т.д.) выводятся как комментарий. # - комментарий
  - номера тестов берутся из файлов в папке tests (по test_pat) и из
    диапазонов групп, имена ответов - по corr_pat
  - предупреждаю, если группы пересекаются, если requires ссылается на
    несуществующую группу или если в номерах тестов есть пропуски
